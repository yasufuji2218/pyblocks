# 練習問題・採点の設計

## 既存実装との差分

既存はBlockly編集・Python生成・Pyodide Worker実行・入力・ゆっくり実行・ライブラリ・CSV・グラフを実装していた。問題管理、採点、ヒントは存在しなかった。既存実行経路を保持し、採点専用のWorkerを追加した。

## ファイルの責務

- `public/problems/catalog.json`：問題データ12問。新規問題はこの配列へ追加する。
- `public/problem-model.js`：データ検証、ブロック走査、エイリアス、固定判定、ヒント段階。
- `public/grading.js`：副作用を持たない採点・部分点・完全正解・フィードバック。
- `public/test-runner.js`：テストごとのWorker生成、進捗、タイムアウト、キャンセル。
- `public/grading-worker.js`：実Pythonで入力・出力・最終状態・関数呼び出しを取得。
- `public/exercise-ui.js`：問題選択、使用ブロック制限、固定保護、ヒント、採点結果。

## 問題の追加

catalog.jsonの既存レコードをコピーし、一意のid、course、category、difficulty（1〜5）、type（build/fill/fix/free）、title、description、instructionを設定する。問題一覧はJSONから自動生成され、追加時にUI修正は不要。

available_blocks / required_blocks / forbidden_blocksはBlocklyのtype名を使う。`print` / `for` / `while` / `if` / `function` / `call`の短縮名も利用できる。available_blocksは空にできない。全ブロック許可の場合も使えるtypeを明示する。

initial_blocksとsolution.workspaceはBlocklyのJSONワークスペース保存形式（variablesとblocks）である。初期配置なしは`{"blocks":{"languageVersion":0,"blocks":[]}}`。固定したい個々のブロックに`"locked":true`と安定した`id`を付ける。子ブロックまで固定したい場合は子にも付ける。固定ブロックの未接続の穴へのブロック接続は許可する。

固定はBlocklyの移動・削除・編集フラグと、変更イベント後の状態検査の両方で守る。親ごとの削除・移動、無効化、変数名の変更も検出して直前の有効な状態へ戻す。採点時にも再検査する。

test_casesはinput（文字列配列）、expected_output（文字列）、visibility（public/hidden）。必要ならexpected_stateに変数名とJSON値を指定する。入力プロンプトは採点出力に含めず、inputの返す値だけを供給する。入力が不足するとEOFError。出力比較は改行コードと末尾の改行だけを正規化し、空白・数値表記は区別する。

grading.scoreはoutput、test_cases、required_blocks、forbidden_blocks、available_blocks、state、nesting、functions、lockedの配点。合計100にする。outputは公開テスト出力の成功率、test_casesは全ケースの出力と状態の成功率、required_blocksは必須typeの充足率。必須構造には無効化されたブロックを数えない。

grading.completion_requirementsの全項目が100%達成した場合に完全正解。加えて実行エラー・タイムアウトがなく、使用ブロック・禁止ブロック・固定条件を満たす必要がある。スコアだけでは完全正解にならない。今回の12問は全テスト成功と必須ブロック充足を完全正解条件に含める。

grading.nestingは`[["for","if","print"]]`のような包含経路。入力内の子孫関係で判定し、単なる前後接続は包含とみなさない。grading.functionsは実行時に呼び出されるべき関数名の配列。expected_stateはBlockly変数名をPython識別子へ対応付けて判定する。名前を限定する問題ではその名前をinstructionで明示する。

grading.timeout_msは100〜10000、既定3000。環境読み込み時間（最大180秒）と実行時間を分離する。1ケースごとに新しいWorkerとPython環境で実行し、終了・中止・時間切れ時はWorkerをterminateする。出力上限64000文字。OS上でPythonを実行しない。

hintsはlevel（1〜4）とtext。「次のヒント」で1段ずつ表示する。grading.feedback_stepsで試行回数に応じた補足を設定できる。模範解答は通常の学習画面に表示しない。

## 初期問題

12問：print、変数穴埋め、演算修正、input、if、for修正、while、list穴埋め、関数、math、ネスト総合、合計総合。全4形式、Level 1〜5を含む。入力によって結果が変わる問題には2〜3件の隠しテストを用意した。

## 隠しテストと保存

隠しテストの入力・期待値・実出力・生エラーは結果UIに出さず、成功件数だけ表示する。ただし本アプリはローカル学習用で、問題JSONや採点コードをブラウザーに配信する。開発者ツールやローカルファイルを調べる利用者に対して秘密を保つ試験システムではない。厳格な秘匿にはサーバー側の採点基盤が別途必要。

自由編集の状態を保持して練習へ移り、終了時に復元する。練習中は自由編集の自動保存を上書きしない。問題の回答・試行回数はこのページ内だけで保持し、再読み込みで練習を終了する。進捗アカウント管理は対象外。

## 検証手順

`node --test test/*.test.js`：スキーマ、制限、固定、部分点、完全正解条件、公開・隠し、ネスト、状態、関数、エラー、ヒント。

実Pythonで模範解答を検証する場合、PowerShellで`$env:PYBLOCKS_QA='1'`を設定して`node server.mjs`を起動し、`http://127.0.0.1:4173/exercise-qa.html`のボタンを押す。通常起動時はこのページを配信しない。12問・29ケースを実行する。`scripts/build-problems.mjs`は初期データの作成用であり、通常運用で実行する必要はない（実行するとcatalog.jsonを再生成する）。

## 2026-11-01 採点精度の修正

`executionBlocks(state)`で全配置・実行構造・孤立の3集合を取得する。トップレベルの処理スタックからnext、statement/value入力、shadowを辿る。裸の値・演算ブロックは開始点にしない。関数定義は到達可能な呼び出しから辿り、相互再帰でも各定義を1回だけ処理する。無効な処理の子は除き、後続のnextは引き続き調べる。Blocklyは離れたトップレベルの処理スタックも実行するので、「画面で離れている」ことだけでは孤立扱いしない。

required_blocksとnestingは実行構造のみを見る。forbidden_blocksも同じだが、問題ルートの`forbidden_block_scope`を`workspace`にすると全配置（有効ブロック）を対象にできる。既定は`executable`。使用可能ブロックと固定保持は従来どおり全配置を検査する。

既存のnestingに表示と演算・リスト長・関数呼び出し等の接続経路を追加した。`grading.output_variables`は表示の入力内で参照すべき変数名の配列であり、同じ変数の最終状態だけで合格させないための条件。これらの接続条件はnestingの判定・配点に含む。

`grading.functions`は従来の関数名文字列に加え、`{name:"double",params:["n"],returns:true}`形式を受け付ける。定義・引数・接続された戻り値式・全テストでの実呼び出しを確認する。関数の実行記録だけを偽の定義の代わりには使わない。

孤立した必須ブロックがある場合は「実際のプログラムには接続されていません」と案内する。構造条件にも部分点を割り当て、出力が正しい場合も接続条件不足なら減点する。

### 現時点の限界

- executableは静的な実行構造であり、各テストで全ブロックを通った証明ではない。常に偽の分岐、意味のない計算、別名関数を経由する呼び出しまで意味解析する仕組みはない。
- 接続経路は直接の包含関係で検査する。中間変数を使った等価な解き方には不合格になるものがある。変数をまたぐ一般的なデータフロー解析は未実装。
- 有限個の公開・隠し入力のため、全入力を網羅した正しさや、テスト値だけに合わせた条件分岐の排除は保証しない。
- 新しい処理ブロックを追加する際はproblem-model.jsのstatementTypesにも登録する。関数定義は呼び出し到達性で別途扱う。
- print_01は固定の文字列表示そのものが目的のため、文字列の直接表示が正解となる。

## 耐性テストによる追加修正（最新版）

以前の静的な構造条件に加え、grading.learningを採点する。grading-code.jsは採点時だけ各値の評価・処理の通過にブロックIDを付け、grading-worker.jsがexecutedとvaluesを返す。learning-evidence.jsは宣言的なtype/fields/variable/inputs/next/anyOf/observedパターンを実行された構造と照合する。関数定義は実呼び出しと戻り値式の評価を確認する。表示・保存・通常実行のコードに記録関数は加えない。

配点は公開出力30・全ケース30・必須ブロック20・学習目的20。完全正解でなければ99点以下、学習目的未達は59点以下、実行エラー／時間切れ／固定・使用・禁止違反は49点以下。最終状態や関数など、配点のない条件も完全正解に必要である。

標準採点は各ケースで新しいWorkerを起動・破棄する。QA専用の信頼済みコードによる大量検証だけはランタイムを再利用し、各ケースのPythonグローバル辞書を新規作成する。値の記録は1ブロック8種類・1値2048文字まで。

隠しケースは計12件追加し、全体で41ケース。直接の接続パターンを要求するため、中間変数や別の同値な式による正しい別解を受理できない場合がある。これは未対応のデータフロー解析とともに継続課題である。実行済み構造のテスト全体での和集合は、全入力で同じ計算を行う証明ではない。
